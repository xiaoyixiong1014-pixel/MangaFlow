## 追加：③ 分镜设计 / ④ 内容生成 讨论结论（用户均以"可以"默认接受）

**③ 分镜设计**：
- 拆解粒度=成本档位，需**实时显示预估积分**（"当前 42 个镜头，预估消耗 X 积分"），让用户在拆解阶段就感知成本。
- 提供"镜头密度"三档（精简/标准/密集），原 SB-07 已有密度，新增的是**成本可见**。
- **拆分/合并分镜支持"文字级操作"**（把一句对白直接劈成两镜头），这是体验分水岭。
- 节奏曲线（原 SB-05）建议改为**文字化时长预警**（如"第 3 场连续 5 个镜头都是 3 秒，节奏偏平"），可定位可执行。
- 连续性检查（SB-06，原准确率 ≥70%）策略改为**只报高置信度，宁可漏报不要误报**，做窄而准。
- **分镜的"涉及角色/场景"必须强绑资产 ID**（实体链接），歧义时标黄提示确认——原 PRD 未明确，是上游一致性最后一公里。
- **投递画布的触发引导**：同一分镜重生成 ≥3 次仍不满意时自动提示"是否投递到画布自由精修"——双引擎串联的最佳触点。

**④ 内容生成**：
- 默认路径**关键帧 → 图生视频**（关键帧便宜可反复调，视频贵）；保留"跳过关键帧"通道但标注更贵更不可控。
- **批量前"打样"机制**：首批强制试生 1-3 张，用户确认风格后才放开全量批量（防止 40 张全废）。
- **失败重试的成本归属**（命门）：提交冻结积分 → 成功才扣；平台故障（超时/限流/服务错误）自动重试**由平台承担**；内容违规终止**不计费**；用户主动取消/重生成按规则处理。用户永不为失败任务付费。
- 任务面板给**预估剩余时间**而非百分比；支持生成期间继续编辑其他分镜；完成后站内+浏览器双通知。
- **BGM 版权风险**：只用平台自有免版权曲库 + 用户自带，需提前过法务（用户发布侵权，平台可能共担责任）。
- **配音时长回写分镜**：配音实际时长 ≠ 分镜预计时长，需自动回写并提示用户选择（压缩语速/延长镜头/截断对白）——原 PRD 未覆盖。
- **增量合成**：只重合成受影响片段再拼接（3 分钟 → 几秒），否则局部重生成价值减半。

**⑤ 审核与发布 讨论结论**（用户以"可以"默认接受）：
- 审核设计为**三级闸门**：闸门一 生成时（文本/图像/视频机审，尽早拦成本最低）→ 闸门二 合成后（成片整体审核 + 隐形溯源水印）→ 闸门三 导出/分享（最终校验、多比例输出前复核、留档）。
- **处置分三级**：通过放行 / 疑似→人工复核（**只锁导出，不锁编辑**）/ 违规→立即终止（定位到具体镜头）。
- 核心原则：**尽早拦 + 说得清 + 能申诉**；驳回提示必须定位到具体镜头并给可操作建议（如"第 12 镜疑似暴力，建议调整提示词或替换关键帧"），不得笼统说"内容违规"。
- **多比例输出**：改为在**关键帧阶段按目标比例生成**（输出比例在项目创建时确定），事后智能裁剪仅作降级方案（竖转横硬裁即废片）。
- **分享链接安全**：加水印防搬运、默认不被搜索引擎索引、支持随时撤回、可要求登录。
- **一键发布到平台（R-07）移出 MVP**，独立立项（抖音/视频号 API 审批周期长、需企业资质）。
- **成片版本留档**：保留最近 N 个成片版本，可对比可回退（用户"改 3 次发现还是第一版好"是常态）。

**⑥ AI 画布 讨论结论**（用户以"可以"默认接受）：
- 定位纠偏：画布不是"画画工具"，而是**可视化工作流编排器**（每节点=一步创作，每连线=一次数据流）。
- **画布最大风险是门槛而非技术**：必须做三件套 —— 预设模板（从剧本生成分镜图/角色三视图/风格试验）+ 助手引导（自然语言起步）+ 空态引导卡片（不给空白画布）。
- **双引擎心智**：Studio = "我要做完一部片子"（有序/批量/可交付）；画布 = "我要探索、精修、试验"（自由/试错/组合）；两边互相留入口。
- **一句话生成子图须"先预览、后落地"**：先生成预览（缩略图+节点清单），用户确认后才画到画布。
- **DAG 增量执行必须做**：改任一节点仅重算该节点及下游，未变更上游复用缓存 —— 这是画布"能反复试"的技术前提，没有它画布不成立。
- **插件安全硬性要求**：沙箱运行 + 权限声明与显式授权（如"该插件申请读取画布节点、调用图像生成"）+ 市场人工审核；即使插件功能后置 P2，安全框架也要提前定。
- **画布产物回流需自动补特征提取**（画布产物无特征向量，直接入库会断链），并标记来源为"画布产物"。
- 循环需求用**逻辑节点显式语义**解决（如"重试 N 次直到满足"），不放开画布成环。

**⑦ 平台与智能体层 讨论结论**（用户以"可以"默认接受）：
- 模型路由中心**双层结构**：逻辑模型层（业务视角，按能力抽象：文本/图像/视频/TTS）+ 路由决策（优先级/健康状态/成本/三级配置）+ 渠道层（上游托管，主备 + 自有 Key）。
- 用户自有 API Key 建议采用「**收基础费**」模式（低价积分只 cover 存储/带宽/编排成本）→ **待商务确认**（标记为待确认项）。
- 模型降级须**提示用户**，不静默替换。
- 积分规则用户侧**极简暴露**：只露「本次消耗 + 剩余额度」，计算逻辑锁后台。
- 配额耗尽**软着陆**：已提交任务继续完成，只限新任务（不半路掐断合成）。
- **不向用户暴露多智能体架构**（重要产品判断），仅异常时以"系统在把关"口径呈现（如"一致性 Agent 检测到第 7 镜面部偏差，已自动重生成"）。
- 意图识别失败兜底为「**反问**」而非「猜测」。
- 底线：资金三件套（幂等/对账/资损）为排期红线不可砍；管理员高危操作留痕+二次确认+建议双人复核；长任务（Deep Agents 解析原著）开始前明确预估时长与积分。
