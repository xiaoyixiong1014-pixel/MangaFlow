## 竞品分析：VOZEB PRO（vozeb.com）短剧创作链路

**任务**：分析 `https://www.vozeb.com/create` 创作短剧链路的各功能实现方式。

**产出**：`项目开发文档/VOZEB PRO 短剧创作链路实现分析 V1.0.md`

**取证方式**：`/create` 为登录态客户端渲染，无法抓 DOM/网络；经官方开源仓库文档（features.mdx / project-structure.mdx / page-gallery.mdx / README）重建，该仓库路由（/create /drama /canvas /prompts /assets /billing /profile）与站点逐一吻合，判定为同一产品在线实例。仓库：`csyqlz/VOZEB-PRO`（Next.js 全栈）。

### 该产品链路（关键事实）
1. **`/create` 是统一创作 Agent 会话页，不是短剧页**；图片/视频/音频/文本问答全部收敛进同一入口，`/image`、`/video` 仅为兼容重定向。短剧独立入口为 `/drama`。
2. **短剧编辑器按「集」推进四个阶段**：① 剧本（长文导入/自动分集/结构化分析/确认 Gate）→ ② 内容审核（人工确认 Gate）→ ③ 分镜与镜头设计（镜头标题/画面/对白/旁白/字幕/连续性 + 单帧/首尾帧 + 分镜驱动/直接生成/参考图三种视频模式）→ ④ 镜头生成（图片+视频）。之后是音频（原声/AI 配音/静音）→ 字幕时间轴 → 镜头转码 → FFmpeg 整集合成 → 剪映草稿/版本快照/恢复/取消/下载。
3. **角色/场景/道具/线索走独立项目资产入口**，维护"参考图 + 当前基准"，不在四阶段内。
4. **架构**：Next.js 单体全栈；`app/api/route.ts` 只做入参/鉴权/响应映射，业务下沉 `lib/server`，Repository → PostgreSQL 16；媒体本地目录或 S3，页面 WebP 预览 + 下载原件 + 上游短期签名 URL。
5. **三个可复用机制**：逻辑模型↔真实渠道分离（`logical-model-router.ts`）；单次创建+轮询同任务幂等（`clientRequestId`）；积分预扣→终态结算→失败幂等退款。
6. **内部规划提示词/模型理由/创作简报/视觉复盘不写入对话、不持久化**。

### 与 MangaFlow 的差距结论
平台层（PL/SYS/S-03 生成）我们同级或更细；差距集中在短剧业务链路完成度五项：**S-06 多集管理、SB-06 连续性、P-03/P-08 首尾帧与参考图模式、剧本级审核 Gate（我们是三级闸门，无剧本闸门）、剪映草稿交付**。
