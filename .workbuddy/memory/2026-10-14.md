## 剧本创作模块不足评估 V1.1（升级：新增范式级缺口）

**用户明示的期望范式（2026-10-14，重要——这是"剧本创作"的定义本身）**：
创意输入 → **②Agent 明确角色情况（角色设定）** → **③分集大纲** → **④把每一集文章输出给用户** → **⑤用户自行修改或 AI 优化**

**核对结论**：该范式**整体未实现**。当前实现是"单次 LLM 一把成稿"（title+logline+三幕outline+3~6场次JSON，单集），与期望存在 **4 处结构性错位**：
1. 角色无前置设定（角色是生成后"抽取"出来的，顺序颠倒）
2. 无分集概念（只有三幕叙事结构；`episodes` 表无 logline/outline 字段）
3. 产出形态错位（给场次 JSON，不是"每一集文章"；且仅单集）
4. 无分阶段确认（只有 1 个 HITL 点）

**关键判断（重要）**：**技术能力已全部就绪，缺的只是编排** —— interrupt/Command(MA-08)、Send(MA-10)、子图(MA-09，已有审核/一致性子图范例)、PostgresSaver(MA-05)、llm_adapter 统一适配 **全部已实现**，只是没串成"剧本子图"。

**解决方案（已写入文档 §3.6）**：
- 三段式剧本子图：`input → character_planner → [interrupt] → episode_planner → [interrupt] → episode_writer×N(Send并行) → [interrupt] → optimize → extract_supplement`
- 数据模型：`projects.script_phase` 状态机(idea→characters→outline→body)；`characters` 增 role_type/age/personality/motivation/arc/relations/confirmed_at；`episodes` 增 logline/outline(核心事件/情绪走向/出场角色ID/时长)/confirmed_at；`scripts` 复用承载分集正文（已有 uk(project_id, episode_id)）
- 新增 14 个接口（角色 5 / 大纲 4 / 正文 3 / 优化 2）
- 3 个新 Agent：character_planner / episode_planner / episode_writer（均严格 JSON 输出）；RD-01 忠实度差异化落地在这三个 Agent
- 前端：ScriptView 升级为四步（创意→角色卡→分集大纲→分集正文长文编辑 + AI 四粒度 diff）
- 兼容：保留"快速模式"（script_phase=NULL）；存量数据可"升级为分阶段"；S-10 抽取降级为"补充道具/场景/新角色"→ **顺带消解 V1.0 的【不足1】抽取源问题**

**用户 5 步方案要点**：①左中右三栏（左=常驻参数栏/中=故事设定→分集大纲→剧本正文三卡片/右=AI 对话区）②按输入类型分流（一句话创意→自动加载"AI 正在构建故事宇宙"→产出故事设定；小说/大纲→解析进度条→直接出分集大纲+"预计 N 集是否确认"）③三阶段定稿（故事设定可编辑→分集大纲支持**单集重生成**→正文符合漫剧格式【场景：…】【镜头：特写】）④**对话式共创**（自然语言精准改中间工作区+快捷 chips 三组+版本历史可回退）⑤下游格式化拆解（人物→立绘/场景→概念图/按镜头切分→画布节点）。

**现状诊断（另核实代码）**：
- 冗余定位：`StepIdea.vue` 把 ①双栏「原始输入/AI生成」(:1018-1098 重复) ②「大纲导航+场景卡列表」(:1114-1167 **越界**，属后续步骤) ③引导条/工具行/体检/快速模式开关 ④AI 助手抽屉 全堆在"创意"一步。根因：步骤按"数据阶段"划分而非"用户动作"。
